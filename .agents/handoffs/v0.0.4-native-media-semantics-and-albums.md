# Preserve native Telegram media semantics and publish albums

## A. Metadata

Approved by the user on 2026-11-11 for implementation.

## B. Requirements

### Problem

Source-native video is classified by the gotd decoder, but the shared publisher
converts its `rpc.Media.Type == "video"` to `SendMedia.Kind == "document"`.
The destination therefore receives document semantics despite transferring the
original bytes. Video width, height, streaming metadata and round-video
distinction are also absent from the current normalized media DTO / worker send
payload. Existing automation observations carry `grouped_id` into durable event
storage, but source history/API messages do not currently expose it and the
publishing endpoint accepts only one source message/media item.

### Desired behavior

- Classify source media only from authoritative MTProto constructor/attributes:
  photo → photo; `DocumentAttributeVideo` → video (round video distinct or an
  explicit unsupported result); `DocumentAttributeAudio.voice` → voice; audio
  without voice → audio; otherwise document. MIME and filename never promote a
  document.
- Preserve supported metadata, caption text/entities and source media
  identity across normalization, RPC, source download and destination upload.
- Send native photo/video/voice/audio/document MTProto request forms without
  silent downgrade; use source worker for download and destination worker for
  upload/send.
- Correlate album members by `(source connection/network, source channel,
  grouped_id)`, recover and deduplicate members across history/update boundaries,
  preserve order/captions, and publish valid collections natively through
  `messages.sendMultiMedia` with the required `messages.uploadMedia` preparation.
- Integrate whole-album manual publishing, durable/idempotent workflow publishing,
  asynchronous Direct Send multi-file requests, grouped viewer rendering and
  composer selection without breaking single-message behavior.
- Report partial preparation and ambiguous remote outcomes honestly; never
  silently drop/split an album or blindly retry an uncertain send.

### Acceptance criteria

- [ ] Native video remains video through shared publishing and outgoing
  `InputMediaUploadedDocument` includes source-preserving video attributes;
  `ForceFile` is not set.
- [ ] Photo, voice, ordinary audio, generic document and MP4-document-without
  native video attributes retain their distinct semantics.
- [ ] Round video is preserved distinctly where supported, otherwise explicitly
  refused; dimensions, duration, streaming flag and MIME are propagated when
  actually known/applicable.
- [ ] Tests assert the outgoing MTProto request, not only a DTO label.
- [ ] Album identity is connection/network + channel + grouped ID; ordering,
  entities, captions and duplicate handling are tested across pages and updates.
- [ ] Album send prepares every item with `uploadMedia`, builds
  `InputSingleMedia`, calls `sendMultiMedia`, and confirms destination message
  IDs/grouping; no silent standalone fallback.
- [ ] Workflow and Direct Send album behavior is durable, idempotent, bounded
  (2–10 items unless server capabilities say otherwise), and backward-compatible
  with single-file sends.
- [ ] Channel Explorer shows one ordered gallery for an album and manual
  publishing previews/publishes all members; composer can select/reorder/remove
  multiple compatible files.
- [ ] Focused backend/frontend tests, builds, docs checks and repository checks
  pass. Live destination verification is reported separately and only if
  authorized credentials/endpoints are actually available.

### Out of scope

- Transcoding, FFmpeg, replacing gotd, redesigning the publishing dialog,
  rewriting the workflow engine, a second queue/upload system, changing
  permissions, unrelated administration or webhook changes, and production
  publishing/deployment.

### Symbols and contracts

- `gotdclient.MediaType(tg.MessageMediaClass) string` and
  `documentType(*tg.Document) string` use MTProto metadata; source video already
  classifies as `video`.
- `gotdclient.normalizeMessage(*tg.Message, users)` does not copy `Message.GroupedID`
  to the public domain message. `rpc.Message` likewise has no `grouped_id`.
- `publishing.(*Service).buildSend` downloads source bytes through the resolved
  source `Worker.Media`, then forms `rpc.SendMedia` from normalized metadata.
- `publishing.sendKind(*rpc.Media)` handles photo/voice/audio and otherwise
  returns document. This is the verified video-to-document conversion point.
- `gotdclient.(*Manager).SendMessage` uploads with the destination client's
  uploader; `sendMediaInput` selects destination `InputMedia` and
  `MessagesSendMedia` sends it. No album method is currently exposed in the
  worker RPC contract.
- Event `GroupedID` is already `int64`; public JSON should encode opaque 64-bit
  grouping IDs as strings if exposed to JavaScript.

### Dependencies and call paths

- Manual publish and Workflow share `publishing.PublishTelegram` / `Publish`,
  then `buildSend` → source worker `Media` → destination worker `SendMessage` →
  `gotdclient.SendMessage` → gotd upload + `messages.sendMedia`.
- Source message decode is `gotdclient.Message`/`History` → `normalizeMessage`
  → `tgapi` → worker → `rpc` JSON → gateway/API.
- Automation update observation is gotd update/backfill → RPC ingest message →
  `events.Ingestor` → SQLite `automation_events`; grouped ID is already present
  on that side, but there is no collected album object or publication unit.
- Direct Send is the existing durable staged operation/queue path and currently
  accepts one `file`; extend this contract and operation model, do not create a
  second queue.

## D. Implementation plan

1. **`internal/automation/publishing/voice_test.go`** — keep the new regression
   assertion that a source `rpc.Media{Type:"video"}` reaches destination worker
   as kind `video`; expand table coverage for MIME/filename impostors and test
   caption/entity/source-vs-destination behavior.
2. **`internal/tgapi/tgapi.go`, `internal/rpc/rpc.go`** — define the minimal
   stable semantic media descriptor fields (duration, dimensions, streaming,
   round-video as supported, source grouped ID) and backward-compatible optional
   JSON. Keep raw generated MTProto values private.
3. **`internal/gotdclient/channel.go`, `dialogs.go`, `updates.go`** — classify
   exclusively from constructors/attributes; normalize photo/document/video,
   round video and grouped ID; preserve metadata through update and history
   paths. Add source-object regression tests before implementation.
4. **`internal/automation/publishing/send.go`, `internal/gotdclient/send.go`** —
   map source kind without fallback promotion; carry metadata and construct
   correct native `InputMedia` attributes, including video dimensions and only
   valid streaming support. Preserve no-force-file and explicit unsupported
   behavior. Assert actual gotd outgoing request through `tgtest`.
5. **RPC/worker send contracts and tests** — propagate semantic metadata without
   altering the established source-download/destination-upload split. Add JSON
   round-trip coverage and cross-connection tests.
6. **History/update album correlation and persistence** — add logical album
   identity `(network/client, Telegram channel, grouped_id)`, stable ordered
   member dedupe, bounded neighbor recovery across pagination, and bounded update
   coalescing/reconnect recovery. Design migrations only after choosing durable
   state consistent with current queue/events; preserve partial/missing states.
7. **Native album transport** — inspect installed gotd types; add a shared album
   send operation that downloads all source items, uploads all bytes to the
   destination, prepares each using the actual `messages.uploadMedia` sequence,
   creates ordered `InputSingleMedia` values and calls `messages.sendMultiMedia`.
   Persist per-member/result IDs and classify ambiguous outcome as unknown.
8. **Manual and Workflow publishing** — accept whole album identity/member set,
   preserve per-item caption/entities, reuse shared publisher and destination
   idempotency; ensure AI text polishing does not remove media. Reject unsupported
   destination album capability explicitly.
9. **Direct Send** — extend existing multipart contract to repeated ordered files
   plus explicit kind metadata; stage all before enqueue, one durable operation,
   2–10 compatibility validation, status/recovery and returned sent IDs. Preserve
   legacy `payload` + `file` behavior.
10. **Frontend/API/docs** — expose grouped ID as a precision-safe string and
    sufficient media metadata; dedupe gallery across pages without destabilizing
    anchors; add album publish preview and composer multi-select/reorder using
    existing dialog/Sheet. Update route docs via docsgen only.
11. Run focused regression tests and builds first, then the established Go,
    docs/apidocs and web typecheck/tests/build checks. Attempt real destination
    checks only with authorized configured test connections; record unavailability
    otherwise.
