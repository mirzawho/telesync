# Polish message actions and floating chat footer

## A. Metadata

Prepared under the mandatory test-first workflow. No production implementation has started.

## B. Requirements

### Problem

`ChannelMessageItem` currently places `MessageActions` at `absolute -left-9 top-0`, which is physically top-left in its RTL context. `ChannelMessagesPane` renders the timeline and shared composer in normal flow: the scroller does not reserve dynamic footer clearance and messages cannot visibly pass underneath a floating footer.

### Desired behavior

- Anchor the existing message action menu at the physical bottom-right of its own bubble, preserving handlers, permissions, and clear space for bubble content/reactions/publish action/footer metadata.
- Render the existing composer as an absolute, pane-local `bg-background/80 backdrop-blur-xl` overlay with no heavy outer box.
- Observe actual footer height and apply matching scroll-content bottom clearance; position Jump-to-latest above the footer.
- Preserve paging, initial newest positioning, follow/anchor behavior, shared Send/Edit mode, attachment previews/Sheet, and responsive safe area.

### Acceptance criteria

- [x] Menu is physically bottom-right of the individual bubble and does not collide with content/actions/metadata.
- [x] Footer is absolute within the message pane, translucent/blurred, not viewport-fixed or a card.
- [x] ResizeObserver-driven footer height updates timeline bottom padding and jump control position.
- [x] Last message remains reachable and existing paging/scroll anchoring/follow behavior stays intact.
- [x] Existing Send/Edit/Delete/publish/attachment functionality remains unchanged.
- [x] Focused tests, frontend typecheck, tests, build, and `git diff --check` pass; browser availability/results recorded.

### Out of scope

No backend or message operation changes; no channel list, global navigation, or unrelated component redesign; no new dependencies.

### Symbols and contracts

- `ChannelMessageItem()` builds `data-slot="message-bubble"` wrapper and `Bubble`; current menu wrapper is absolute `-left-9 top-0`, outside `Bubble`.
- `ChannelMessagesPane()` keeps `scroller` and `content` refs, with initial newest scroll at first page, `capture()/restore()` for prepend anchoring, near-bottom following, and sentinel IntersectionObservers rooted at `scroller`.
- The current `<div className="relative min-h-0 flex-1">` already provides a suitable pane-local positioning context. Scroller fills it; jump control is currently bottom-4; composer is a sibling outside it.
- Existing composer can grow due to text, edit context, errors and attachments; observe its rendered wrapper rather than using fixed padding.

### Dependencies and call paths

- Pane renders `ChannelMessageItem` for each message; item renders `MessageActions` only when edit/delete permissions are available.
- `ChannelMessagesPane` → timeline scroller/content, paging/follow/anchor callbacks; footer placement and measured height should alter geometry only, not these callbacks.
- Floating footer should live inside the existing relative pane wrapper; dynamic padding belongs on timeline content so `scrollHeight`/scroll-to-bottom includes clearance.

## D. Implementation plan

1. `message-item.tsx` — move the existing `MessageActions` wrapper inside the individual `Bubble`, anchor using physical `right` and `bottom` utilities, and reserve bubble padding for the button; keep reaction and publish control space distinct.
2. `channel-messages-pane.tsx` — add a footer ref and stateful measured height; observe actual wrapper with `ResizeObserver`. Keep the existing relative pane context; move the existing footer into it as an absolute bottom overlay, include safe-area padding, use translucent blur styling, and remove extra border/container appearance.
3. `channel-messages-pane.tsx` — put dynamic `paddingBottom` on timeline content based on measured footer height (plus existing content spacing); move Jump-to-latest bottom offset to measured height plus gap. Preserve scroller ref, observers, refs, keys and scroll callbacks.

5. `chat-layout.test.tsx` — retain the new Red tests and expand assertions for action button placement/accessibility, pane-local absolute footer (not fixed), blur, dynamic clearance hook, and jump offset wiring. Keep existing timeline/anchor unit suites unchanged as regression tests.
