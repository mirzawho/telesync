# Redesign Add Telegram Account dialog UX

## A. Metadata

Frontend-only UX refinement for the existing personal Telegram account login wizard at `/admin/accounts`.

## B. Requirements

### Problem

`account-login-wizard.tsx` currently presents a 520px dialog with a footer cancel button, technical server keys and capability copy in server rows, and horizontally arranged phone/code/password actions. The requested design is a compact Persian RTL dialog with one close control, compact server rows, vertically stacked actions, and consistent treatment of phone, code, 2FA, and success steps.

### Desired behavior

- Remove the footer `انصراف` action and preserve the existing X close mechanism and its cancellation/cleanup behavior.
- Use a mobile-safe dialog up to 440px, rounded and consistently spaced.
- Render selectable server rows as nonwrapping `flex-nowrap` rows with the server icon physically right and ArrowLeft physically left; omit technical keys and secondary technical/capability labels.
- Keep immediate server-to-phone transition and preserve safe form state on back navigation.
- Give phone, verification-code, and 2FA steps a consistent vertical action stack, full-width primary action, and secondary Back action as supported.
- Keep validation deferred until blur/submission, maintain field focus, loading protection, resend countdown, password visibility, and success identity.
- Do not change login API calls, state transitions, session behavior, or error mapping.

### Acceptance criteria

- [ ] No `انصراف` button in any wizard state; exactly the existing X close control.
- [ ] Server rows use `flex-nowrap`, `justify-between`, `gap-3`, `min-w-0`, subtle neutral hover, and visible keyboard focus.
- [ ] Server name does not wrap; icon sits at physical right and ArrowLeft at physical left.
- [ ] Phone view has the specified title/subtitle, selected server display name, tel input, inline deferred validation, and vertically stacked actions.
- [ ] Code and 2FA use the same compact hierarchy and vertical full-width actions; code focus/countdown and 2FA show/hide remain.
- [ ] Back navigation preserves safe phone/code state and never restores a submitted 2FA password.
- [ ] Auth API calls and request contracts remain unchanged.
- [ ] Focused frontend tests, full frontend tests, typecheck, and production build pass.
- [ ] Mobile RTL layout has no horizontal overflow.

### Out of scope

- Backend, MTProto, persistence, and public API changes.
- My Accounts table, Dashboard, and unrelated components.
- New dependencies, commits, or pushes.

### Symbols and contracts

- `AddAccountWizard` uses `startLogin`, `loginStatus`, `submitLoginCode`, `submitLoginPassword`, `cancelLogin`, and `listMyAccounts`; keep these call sites and payloads unchanged.
- `PhoneForm`, `CodePanel`, and `TwoFactorForm` submit through existing callbacks and use controlled draft state. Phone/code touched state delays empty-field validation until blur or submission.
- `reduceLogin` preserves the phone when returning from the code step, preserves correctable code on a recoverable rejection, and clears the 2FA password at submission.
- `loginViewState` drives code, 2FA, resend, terminal, and success states from the normalized API attempt.
- Shared DialogContent provides the sole X close control; the wizard `cancel` path notifies `onConnected` only for an authenticated account and requests close.

### Dependencies and call paths

- Server row click → `select_server` reducer event → `loginViewState` enters `authenticate` → phone form is rendered immediately.
- Phone form submit → `requestCode` → unchanged `startLogin` with selected `server_key`, method and entered `phone_number`.
- Code/2FA form submit → existing API helper → `applyAttempt`; account lookup waits for the safe owner-scoped account record before success is shown.
- X close/Escape → Dialog `onOpenChange(false)` → wizard `cancel` and open-state cleanup; pending cancellable attempts are canceled by the existing effect.
