# Polish personal accounts table and profile dialog

## A. Metadata

Frontend-only visual change for the existing personal account management UI.
The user explicitly approved this handoff on 2026-11-14 and implementation is
complete.

## B. Requirements

### Problem

`AccountList` currently renders responsive account cards, and
`AccountDetailsContent` renders a vertical technical-field list. The dashboard
already renders compact account cards, but needs the same profile/avatar and
status treatment as the management page.

### Desired behavior

- Replace the personal account cards with an RTL table with identity, server,
  status, last connection, and actions columns. Keep it a table on mobile with
  horizontal scrolling and the actions column sticky at physical left.
- Preserve the page header, add-account action, row-specific menu actions,
  permissions, loading, error, and empty states.
- Redesign the details dialog as a compact centered profile with avatar, name,
  LTR username, status badge, and subtle server label; align four detail
  label/value pairs in two columns. Keep the existing close control, with no
  cancel button. Put diagnostic account ID behind a secondary copy action.
- Keep dashboard layout and compact account presentation; align its account
  avatar, name, server, and status treatments with the management page.
- Keep optional values safe, technical identifiers LTR, and the dialog usable
  on mobile. No backend/API, login/session, Runner, permission, or dependency
  changes.

### Acceptance criteria

- [x] My Accounts renders a semantic table, not cards, on every viewport.
- [x] Table has the five specified columns, aligned cells, nowrap content,
  horizontal overflow, and physical-left sticky Actions.
- [x] Avatar/name/username, server, status badge, date or `—`, and existing
  DropdownMenu actions render correctly.
- [x] Dialog has a centered profile header and compact two-column details;
  optional phone/date values are safe; ID is secondary with Copy.
- [x] Dashboard remains a compact list and shares the account identity/status
  presentation.
- [x] RTL/LTR and mobile layout behavior are covered by focused tests.
- [x] Frontend tests, typecheck, and production build pass.

### Out of scope

- API/backend/login/session/Runner/account permission behavior, global layout,
  unrelated frontend refactors, dependencies, commit, or push.

### Symbols and contracts

- `AccountList({accounts,onAction,now,className})` currently renders a card grid.
- `AccountDetailsContent({account,now})` is an SSR-testable detail presentation.
- `AccountStatusBadge({account})`, `accountTitle`, `accountSubtitle`, and
  `serverLabel` already centralize safe labels and status.
- `connectedAgoLabel` yields relative Persian text and says “never connected”
  when absent/invalid; the request instead calls for a formatted date/time or
  `—`, so the table/dialog need a presentation-level formatter.
- UI package has no `avatar.tsx` primitive at this baseline; using the requested
  shadcn Avatar may require adding a small local UI primitive without a new
  dependency, or confirming another existing account-avatar source.

### Dependencies and call paths

  `onAction(account, action)` handler → unchanged navigation/submission/dialog.
- Account menu “جزئیات حساب” → page state → `AccountDetailsDialog` →
  `AccountDetailsContent`.
- Dashboard loader reads `listMyAccounts`; `PersonalAccountsSection` displays
  the returned account records and does not depend on global server health.
